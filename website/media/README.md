# Homepage demos

All five gallery slides use silent H.264 clips at 1600 × 960 with JPEG posters. The session-management and tmux clips run at 30 fps for 11.6 seconds, within their 12-second countdowns. The other three clips run at 20 fps for 7.6 seconds, within their eight-second countdowns. No model prompts were submitted.

| Clip | Length | Recorded behavior |
| --- | --- | --- |
| `multi-agent-sessions.mp4` | 7.6 s | Actual sidebar clicks switch between installed Claude Code, Codex, and OpenCode CLIs. Four new sessions, including two Claude Code sessions, stay under `orbit-web`. |
| `session-reader.mp4` | 11.6 s | Open **New session**, select Claude Code and start its CLI, read a saved sample conversation, use **Resume** to restore it in the real CLI, and delete a separate saved session into the macOS Trash. |
| `ssh-sessions.mp4` | 7.6 s | Expand and collapse the `dev-desktop` project, switch to the local Claude CLI, and return to a remote conversation. The remote hosts and saved history are fixtures; this clip does not establish a live SSH connection. |
| `tmux-persistence.mp4` | 11.6 s | Run a real Python task in Claude Code's bash mode that hashes 500 disposable project files. Close the tab at about 80/500 files, choose **Keep running**, and click its running sidebar session to reattach. Progress has advanced to about 240/500 files. This clip demonstrates closing and reattaching a tab, rather than quitting and reopening the app. |
| `tabs-split.mp4` | 7.6 s | Switch tabs in the vertical **Open tabs** list, then choose **Add tab to new split view → Terminal**. The shell shows a real Git diff in the sample repository. This clip does not demonstrate reopening tabs at launch. |

Captured on October 5, 2026. The multi-agent, SSH, and tabs clips use the existing isolated JustSessions Showcase app described in [screenshot provenance](../../docs/images/README.md), with production views and models from revision `d14311dce0af7ac94c3222851cfafb8a383e46f1`. The replacement session-management and tmux clips use a separate copy of the existing production app built at `1c965b34fbf3e5fc125ae6a152af7f5a575ec443`. Neither recording required a Swift build. Host and project data are examples.

The replacement production-app copy has its own bundle identifier, preferences, home directory, agent storage, project, and tmux socket directory. It loads three disposable Claude Code JSONL fixtures and uses the normal New, Resume, Delete, and reattach controls. No custom capture shortcut substitutes for these actions. Claude Code loads the sample history without a model request; its CLI reports that this isolated profile is not logged in. The Python task reads and hashes real disposable files, and emits its own progress. The user's app, conversations, and tmux sessions are untouched.

The clips combine timestamped captures of actual UI states: 68 for multi-agent, 73 for SSH, 220 for tmux, 59 for tabs, and 330 for session management. Idle gaps between recording segments are removed, and segment timing is shortened to fit the countdown while preserving UI redraws and progressing task output. The 30 fps encoding does not synthesize intermediate UI states. Frames are scaled without changing their aspect ratio.

macOS captures native sheets separately from their parent window. The replacement clips composite each real sheet over the immediately preceding real app capture. Alert sheets are enlarged to twice their captured resolution for legibility; the larger New session sheet retains its captured size. Antialiased rounded masks remove gray capture corners, and a subtle presentation shadow separates each sheet from the window. No dialog text, controls, or CLI output is recreated. The tmux poster uses the close-tab composite, the session-management poster uses New session, and the tabs poster uses the resulting split view. Other posters use the first frame. Raw captures and timestamps remain in ignored `dist/` folders rather than published assets.

The active slide plays its clip; the existing gallery play/pause button controls both rotation and media. Inactive clips pause, and returning to a slide restarts it. Only the first clip has HTML autoplay, so the remaining clips show their posters until selected. Every clip and poster receives a content-hashed URL. The SSH slide's decorative SVG outlines the host header and project at fixed capture coordinates, outside the app UI.

To replace a clip, capture the same app window at a fixed size, record each frame's timestamp, and encode the sequence with FFmpeg's concat input, H.264, `yuv420p`, no audio, and `+faststart`. Keep the finished clip below its slide countdown. Longer demonstrations specify `data-gallery-duration` in milliseconds; the default is 8000. Update the poster, accessible description, countdown, SSH outline coordinates when applicable, and provenance together. Keep capture files outside the website sources; only finished clips and posters are published.
