# Performance budgets

[Back to requirements](../README.md) · [Performance log](../../development/performance.md)

Each line is a result the project measured and wants kept, with the mechanism that delivers it. A change that removes a mechanism, or touches a hot path listed here, reruns the named measurement and records the result in [performance.md](../../development/performance.md).

Measurement suites live in `Tests/JustSessionsTests/Performance/` and record only with `JUSTSESSIONS_PERF=1`; use a release build (`swift test -c release`). Numbers are from the commits named, on the hardware those commits describe. Treat them as budgets to stay near, not exact thresholds: a clear regression against them needs a reason.

## Method

- Profile a build made like the release (same SDK), with an accessibility client such as Raycast running, and leave the SwiftUI instrument out of CPU profiles. See [How to profile](../../development/performance.md#how-to-profile).
- Activity syncs once a second; a new tab waiting to link refreshes this Mac every 6 seconds and copies an SSH host every 10. A Claude Code tab waiting for a refresh to list the session its CLI moved to (LIV-07) asks once as soon as no refresh of its host runs, then refreshes this Mac at most every 6 seconds, only once that session's transcript has changed, and copies an SSH host 10 seconds after its last copy ended, only once the relay shows something new or that copy failed; each move to another session starts over. On their own, while a workspace window shows on screen, this Mac refreshes every minute and each SSH host every 5 minutes. A host with sessions running in tmux and no tab open is listed every 3 seconds. Don't tighten these without measuring. A conversation map on screen checks its session file once a second on this Mac and every 5 seconds for an SSH copy (PERF-89).
