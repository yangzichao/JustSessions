# Following a tab's CLI, and live names

[Back to requirements](../README.md)

A tab stays linked to the session its CLI is actually in, so its title, sidebar row, activity, and the session reopened at launch all match. The behavior is specified in Gherkin under `Tests/JustSessionsTests/Gherkin/Features` and runs in `make test`.

| ID | Requirement | Origin | Related tests |
| --- | --- | --- | --- |
| LIV-01 | A name set with `/rename` in Claude Code shows in the tab and sidebar row while the tab is open, on this Mac and on SSH hosts with the relay (SSH-90). On an SSH host the relay carries the session id and chosen name in the title; the tab never reads this Mac's registry. Names and session ids are scoped to the host, so a copy of the same session on another host keeps its name. A name given in the app wins. While a tab waits for a refresh to list the session its CLI moved to (LIV-07), the name the CLI gave that session shows on the tab alone, never on the row of the session the tab is still linked to; once the tab links, the session's row takes it too. | `397a5b7`, `2863743`, `d8bf6de9` | `RenameInClaudeCodeTab.feature`, `RemoteClaudeLiveNameTests`, `RemoteClaudeSessionTitleTests`, `RemoteClaudeActivityRelayTests`, `ClaudeSessionSwitchFollowTests` |
| LIV-02 | Names a CLI appends to its files apply within about a second for open tabs on this Mac: Claude Code's `custom-title` line (also relayed on SSH hosts by SSH-90), Pi's `session_info`, Codex's `thread_name` in `session_index.jsonl`. File reading and name extraction run off the main actor; a result for a closed, ended, or relinked tab is discarded. A name given in the app wins. | `20faa90`, `d8bf6de9` | `RenameFromSessionFiles.feature`, `AppendedSessionNameSourceTests`, `AppendedSessionNameFollowingTests`, `RemoteClaudeActivityRelayTests` |

| LIV-07 | A session the CLI moved to that no refresh has listed yet gets one refresh, then the tab links to it. A Claude Code tab keeps asking until a refresh that started after the move lists it. It asks once that ends. After that, on this Mac it asks again once the session's transcript beside the linked session's changes, no sooner than 6 seconds after it last asked; a session elsewhere, as after `/resume` of another project's session, waits for the auto refresh. On an SSH host it asks again 10 seconds after the host's last copy in any window ended, once the relay shows something new since this tab last asked or that copy failed, and less often after 3 failures in a row (SSH-66). It stops once the tab links, its CLI moves on or ends (the tab then names the session it is linked to again), the host is removed, or the tab closes. It doesn't ask a disconnected host (SSH-101), one waiting for **Connect…** in any window, which connecting refreshes, or one the app remembers as out of reach, until that memory ends or is cleared. Every follow uses one shared linking path. | `3119b7f`, `03a8518` | `ReportedLiveSessionSourceTests`, `RemoteClaudeLiveNameTests`, `ClaudeSessionSwitchFollowTests` |
